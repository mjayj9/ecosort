## 완료 조건

- 사용자 미개봉 확인을 AI 추정으로 덮어쓰지 않는다.
- 오염도 숫자/막대 및 AI 자체 확률을 사용자에게 표시하지 않는다.
- 관찰 불가능과 깨끗함을 구분한다. 모름은 0이 아니다.
- 사용 후 미리 보기, 준비 안내, 추가 확인, 촬영 요청, 보류를 구분한다.
- 물품명과 안내는 코드값 및 출처 있는 한국어 템플릿으로 만든다.
- 지역 수거 기준을 검증하지 않은 공통 준비 안내에는 최종 배출 가능 판정을 붙이지 않는다.
- 사용자 답변만 바꿀 때 NVIDIA를 다시 호출하지 않는다.
- 모든 판단은 서버에서 실행하고 Auth/App Check/분석 기록 소유권을 검사한다.
- 자동 테스트와 실제 AI 사진 검증 결과를 구분한다. 정답 없는 사진을 정확도 근거로 사용하지 않는다.

## 필수 반례

1. 미개봉 두유 + 사용 후 안내 → 현재 세척 필요/오염 판정 없음.
2. 미개봉 두유 + 지금 배출 → 내용물 있는 제품의 준비 안내.
3. AI 개봉 추정 + 사용자 미개봉 → 사용자 확인 무시 금지.
4. 내부 안 보이는 용기 → 내부 상태 확인 불가. 확률 0.99도 우회 불가.
5. 내용물 남음 → 바로 배출 가능 판정 금지.
6. 비운 용기 + 잔여물 → 검토된 품목의 준비 안내, 세척 후 상태 확인.
7. 종이팩 세부 종류 불명확 → 일반 종이로 안내하지 않음.
8. 모르겠음 → 같은 질문 강제 반복 금지.
9. 위험물/여러 물품/빈 사진/지원하지 않는 품목 → 구체적인 보류·촬영 안내.
10. 누락/깨진 JSON/자유서술·혼합 언어 → 검증 실패 또는 표준 명칭, 원문 노출 금지.
11. 상태 수정 재시도·동시 수정·새 사진 → 이전 사진/답변 결과 섞임 금지.
12. 타인 scanId/구버전/클라이언트 키·판정 주입 → 요청 거부.

## 검사와 복구 원칙

각 커밋에는 해당 번호의 변경 및 검증 범위를 남긴다. 아직 활성화하지 않은 모듈을 구현 완료 서비스로 표현하지 않는다.
로컬 소스 되돌리기와 Firebase 배포 되돌리기는 별도다. 서버와 APK 계약을 맞춰야 한다.
문제가 나면 현재 작업을 버리는 reset --hard 대신 이전 커밋을 별도 작업 디렉터리에 checkout하여 비교하거나 필요한 커밋을 revert한다.
키는 Firebase Secret/프로세스 환경변수만 사용한다. Git 검사 후 커밋한다.
실제 원본 사진이 없는 미개봉 두유 사례는 규칙 테스트로 먼저 고정하고, 원본 실물 검증 여부를 별도로 보고한다.
